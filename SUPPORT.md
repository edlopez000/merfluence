# Support

Merfluence is a free, volunteer-maintained open-source project. Help is
available through the channels below — please pick the one that matches what you
need, so requests reach the right place.

## Where to go

| What you have                    | Where it goes                                                                                |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| A question, a how-to, or an idea | [GitHub Discussions](https://github.com/edlopez000/merfluence/discussions)                   |
| A bug or a feature request       | [GitHub issues](https://github.com/edlopez000/merfluence/issues/new/choose)                  |
| A support request                | [The service desk](https://lopezedward.atlassian.net/servicedesk/customer/portal/1)          |
| An accessibility barrier         | [ACCESSIBILITY.md](ACCESSIBILITY.md) has the statement; reports to <support@edwardlopez.dev> |
| A private or direct enquiry      | <support@edwardlopez.dev>                                                                    |
| **A security vulnerability**     | **[SECURITY.md](SECURITY.md)** — a private advisory, never a public or shared channel        |

### Questions, how-to, and ideas → Discussions

Anything of the form "how do I…", "is this supposed to…", or "what if it
could…" belongs in
[Discussions](https://github.com/edlopez000/merfluence/discussions). Ask in
**Q&A**; float feature ideas in **Ideas**. Answers there stay searchable for the
next person with the same question.

### Bugs and feature requests → issues

Use the [issue templates](https://github.com/edlopez000/merfluence/issues/new/choose).
The bug template asks for the **Mermaid version pinned on the diagram** and the
**diagram source** — the app ships two Mermaid majors that do not always behave
alike, so a report without those two is usually not reproducible.

### Support requests → the service desk

For anything that needs a tracked, non-public conversation — installation
trouble, Confluence-admin questions, a problem you would rather not describe in
the open — raise a request on the
[service desk](https://lopezedward.atlassian.net/servicedesk/customer/portal/1).

**You do not need an Atlassian account to raise a request there.**

### Private or direct enquiries → email

<support@edwardlopez.dev> reaches the maintainer directly. The service desk is
the better route for anything you want tracked; email is here for the cases
where a ticket is the wrong shape.

### Security vulnerabilities → the advisory process

**Do not report a vulnerability through Discussions, the service desk, issues,
or email.** Merfluence's whole pitch is a security claim, and reports against it
go through GitHub Security Advisories so the channel stays private until a fix
ships. [SECURITY.md](SECURITY.md) has the process, what to include, and the
response times to expect.

## What to expect

Response is best-effort rather than contractual — this is an open-source project
maintained in spare time, not a commercial support contract. Security reports
are the exception and carry the stated timelines in
[SECURITY.md](SECURITY.md#what-to-expect).

Before filing anything, the [README](README.md) covers installation, usage, and
the [current limitations](README.md#limitations) — some reports turn out to be
documented behaviour.
